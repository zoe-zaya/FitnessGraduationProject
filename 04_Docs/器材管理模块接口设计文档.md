# 器材管理模块接口设计文档

**毕设题目**：基于深度学习的健身管理系统  
**版本**：1.0  
**日期**：2026 年 3 月  
**对应文档**：《需求规格说明书》V1.0、《任务书》V1.0

---

## 一、文档概述

### 1.1 编写目的

本文档定义器材管理模块的 API 接口规范，为前端开发（微信小程序）与后端开发（FastAPI）提供统一的交互标准，确保系统满足《需求规格说明书》3.2 节用例分析和《任务书》技术指标要求。

### 1.2 适用范围

本模块涵盖健身器材识别、健身房（器材清单）管理、器材添加/删除/查询等功能。对应《需求规格说明书》中的以下用例：

- 识别健身器材
- 管理健身房（增、删、改、查）
- 添加器材（自动/手动）
- 查看器材
- 删除器材

### 1.3 基础规范

| 项目        | 规范                             |
|:--------- |:------------------------------ |
| **通信协议**  | HTTP/HTTPS                     |
| **数据格式**  | JSON (`application/json`)      |
| **字符编码**  | UTF-8                          |
| **认证方式**  | JWT (JSON Web Token)，Bearer 模式 |
| **基础路径**  | `/api/equipment`               |
| **响应时间**  | 单次识别<2 秒（《任务书》技术指标）            |
| **识别准确率** | ≥85%（《任务书》技术指标）                |

## 二、认证与授权

### 2.1 认证机制

除器材搜索接口外，所有接口需在 Request Header 中携带 Token。

| Header Key      | Header Value            |
|:--------------- |:----------------------- |
| `Authorization` | `Bearer <access_token>` |

### 2.2 通用响应结构

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

### 2.3 通用错误码

| 状态码 | 说明           | 处理建议            |
|:--- |:------------ |:--------------- |
| 200 | 成功           | -               |
| 400 | 请求参数错误       | 检查请求体字段格式       |
| 401 | 未授权/Token 过期 | 跳转登录页重新获取 Token |
| 404 | 资源不存在        | 检查资源 ID 是否正确    |
| 500 | 服务器内部错误      | 联系后端开发排查        |

## 三、接口详细定义

### 3.1 识别健身器材

**接口描述**：上传健身器材图片，系统识别器材类型并返回识别结果。  
**对应用例**：《需求规格说明书》3.2 节"识别健身器材"用例  
**技术指标**：准确率≥85%，响应时间<2 秒（《任务书》）

| 项目               | 内容                      |
|:---------------- |:----------------------- |
| **URL**          | `/api/equipment/detect` |
| **Method**       | `POST`                  |
| **Content-Type** | `multipart/form-data`   |
| **Auth**         | **需要** (Bearer Token)   |

**请求参数**：

| 参数名     | 类型   | 必填  | 说明                   |
|:------- |:---- |:--- |:-------------------- |
| `image` | File | 是   | 健身器材图片（JPG/PNG，<5MB） |

**响应参数**：

```json
{
    "results": [
        {
            "equipment_id": "eq_0",
            "name": "卷腹机",
            "category": "力量训练 - 固定器械",
            "confidence": 0.7192092537879944,
            "target_muscles": [
                "腹直肌",
                "腹外斜肌",
                "核心肌群"
            ],
            "box_coordinates": [
                76.25070571899414,
                142.52780678272248,
                694.848461151123,
                747.7936813116074
            ]
        }
    ],
    "detection_time": 0.498,
    "message": "识别成功"
}
```

**业务规则**：

1. 识别准确率不低于 85%（《任务书》技术指标）
2. 单次识别响应时间不超过 2 秒（《任务书》技术指标）
3. 置信度低于 70% 时提示"识别不确定，请调整拍摄角度重试"（《需求规格说明书》2.2.3）
4. 若图像中存在多个器材，仅返回置信度最高的结果

**异常场景**：

| 场景          | 预期响应                                       |
|:----------- |:------------------------------------------ |
| 图片数据为空      | 400 "图片数据为空"                               |
| 未识别到器材      | 200 results=[], message="未识别到器材，请调整拍摄角度重试" |
| 置信度<70%     | 200 message="识别不确定，请调整拍摄角度重试"              |
| 识别超时 (>2 秒) | 200 message="检测耗时过长，请重试"                   |

**接口描述**：用户创建新的健身房（器材清单）。  
**对应用例**：《需求规格说明书》3.2 节"管理健身房"用例

| 项目               | 内容                         |
|:---------------- |:-------------------------- |
| **URL**          | `/api/equipment/createGym` |
| **Method**       | `POST`                     |
| **Content-Type** | `application/json`         |
| **Auth**         | **需要**                     |

```json
{
  "location_tag": "家附近健身房",
  "description": "24 小时营业，器械较新"
```

| `location_tag` | String | 是   | 归属标签（1-128 字符） |

```json
{
    "inventory_id": "e952f577-4d20-4be6-93f1-a571237150fd",
    "user_id": "8ea3c7f3-3d35-477b-b2ec-d335aa78224f",

    "message": "健身房创建成功"

```

**业务规则**：

1. 用户可创建多个健身房（《需求规格说明书》2.2.2）
2. 创建时必须指定归属标签（《需求规格说明书》2.2.2）
3. 标签可重复使用（多个用户可创建同名清单）

### 3.7 手动添加器材到健身房

**接口描述**：用户通过关键词搜索后手动添加器材到健身房。  
**对应用例**：《需求规格说明书》3.2 节"添加器材——手动添加"用例

| 项目               | 内容                                                  |
|:---------------- |:--------------------------------------------------- |
| **URL**          | `/api/equipment/addEquipment/{inventory_id}/manual` |
| **Method**       | `POST`                                              |
| **Content-Type** | `application/json`                                  |
| **Auth**         | **需要**                                              |

**路径参数**：

| 参数名            | 类型     | 说明     |
|:-------------- |:------ |:------ |
| `inventory_id` | String | 健身房 ID |

**请求参数**：

```json
{
  "inventory_id": "inv_abc123...",
  "equipment_id": "eq_7"
}
```

| 参数名            | 类型     | 必填  | 说明      |
|:-------------- |:------ |:--- |:------- |
| `inventory_id` | String | 是   | 器材清单 ID |
| `equipment_id` | String | 是   | 器材 ID   |

**响应参数**：

```json
{
  "message": "器材添加成功",
  "equipment_name": "哑铃"
}
```

**业务规则**：

1. 用户通过关键词搜索系统器材库（《需求规格说明书》基本事件流 1-2）
2. 选择目标器材后手动加入健身房（《需求规格说明书》基本事件流 3-4）
3. 同一器材不可重复添加

**异常场景**：

| 场景          | 预期响应            |
|:----------- |:--------------- |
| 健身房不存在      | 404 "健身房不存在"    |
| 无权访问        | 404 "无权访问"      |
| 搜索的器材不在器材库中 | 404 "找不到搜索的器材"  |
| 器材已存在于健身房中  | 400 "该器材已在健身房中" |

**接口描述**：基于器材识别结果自动添加器材到健身房。  
**对应用例**：《需求规格说明书》3.2 节"添加器材——自动添加"用例

| 项目               | 内容                                                |
|:---------------- |:------------------------------------------------- |
| **URL**          | `/api/equipment/addEquipment/{inventory_id}/auto` |
| **Method**       | `POST`                                            |
| **Content-Type** | `application/json`                                |
| **Auth**         | **需要**                                            |

**路径参数**：

| 参数名            | 类型     | 说明     |
|:-------------- |:------ |:------ |
| `inventory_id` | String | 健身房 ID |

**请求参数**：

```json
{
  "inventory_id": "inv_abc123...",
  "equipment_id": "eq_7",
  "confidence": 0.92
}
```

| 参数名            | 类型     | 必填  | 说明          |
|:-------------- |:------ |:--- |:----------- |
| `inventory_id` | String | 是   | 器材清单 ID     |
| `equipment_id` | String | 是   | 识别到的器材 ID   |
| `confidence`   | Float  | 是   | 识别置信度 (0-1) |

**响应参数**：

```json
{
  "message": "器材添加成功",
  "equipment_name": "哑铃",
  "confidence": 0.92
}
```

**业务规则**：

1. 基于器材识别结果添加（《需求规格说明书》2.2.2）
2. 置信度低于 70% 时提示用户调整拍摄角度重试（《需求规格说明书》2.2.3）

**异常场景**：

| 场景         | 预期响应                   |
|:---------- |:---------------------- |
| 置信度<70%    | 400 "未识别到器材，请调整拍摄角度重试" |
| 健身房不存在     | 404 "健身房不存在或无权访问"      |
| 器材不存在于器材库中 | 404 "找不到识别的器材"         |
| 器材已存在于健身房中 | 400 "该器材已在健身房中"        |

### 3.11 从健身房中删除器材

**接口描述**：从指定健身房中删除指定器材。  
**对应用例**：《需求规格说明书》3.2 节"删除器材"用例

| 项目         | 内容                                                             |
|:---------- |:-------------------------------------------------------------- |
| **URL**    | `/api/equipment/deleteEquipment/{inventory_id}/{equipment_id}` |
| **Method** | `DELETE`                                                       |
| **Auth**   | **需要**                                                         |

**路径参数**：

| 参数名            | 类型     | 说明     |
|:-------------- |:------ |:------ |
| `inventory_id` | String | 健身房 ID |
| `equipment_id` | String | 器材 ID  |

**响应参数**：

```json
{
  "message": "器材删除成功"
}
```

**异常场景**：

| 场景        | 预期响应             |
|:--------- |:---------------- |
| 无权访问      | 404 "无权访问"       |
| 健身房不存在    | 404 "健身房不存在"     |
| 器材未在该健身房中 | 404 "器材未在该健身房中"  |
| 删除失败      | 500 "删除器材失败，请重试" |
