## 一、业务对象修订

根据新的训练计划生成逻辑，对原需求规格说明书中的业务对象进行修订。主要涉及 `TrainingPlan`（训练计划）、`SessionActionItem`（阶段动作项）以及新增的 `TrainingSchedule`（训练日程）对象。

### 1.1 TrainingPlan（训练计划）

`TrainingPlan` 类的属性与函数的详细说明可查看表 1-1。

**业务规则**：

1. 计划表中不再包含有效期（`valid_days`）和总时长（`total_duration_minutes`）字段。
2. 健身目标仅分为"减脂"和"增肌"两类。
3. 计划必须关联有效器材清单，确保所有推荐动作均可在目标健身房执行。
4. 计划生成时需指定计划类型（减脂计划/增肌计划），增肌计划需指定分化方案。

**表 1-1 TrainingPlan 对象**

| 属性/函数                 | 类型       | 说明                                                                   |
| :-------------------- | :------- | :------------------------------------------------------------------- |
| `planId`              | String   | 计划唯一标识符，系统自动生成                                                       |
| `userId`              | String   | 计划归属用户 ID                                                            |
| `inventoryId`         | String   | 关联器材清单 ID，标识该计划基于哪个健身房的器材配置生成                                        |
| `createTime`          | DateTime | 计划生成时间                                                               |
| `planType`            | String   | 计划类型（"FAT\_LOSS"/"MUSCLE\_GAIN"），决定训练计划类型                            |
| `schemeType`          | String   | 分化方案（仅增肌计划有效："ONE\_SPLIT"/"TWO\_SPLIT"/"THREE\_SPLIT"/"FOUR\_SPLIT"） |
| `cycleRule`           | String   | 训练循环规则（如"练 3 休 1"、"练 2 休 1"等）                                        |
| `status`              | String   | 计划状态（"ACTIVE"/"ARCHIVED"）                                            |
| `generatePlan()`      | 函数       | 启动训练计划生成流程：选择计划类型→系统筛选匹配动作→构建三阶段结构→输出完整计划                            |
| `getWeeklySchedule()` | 函数       | 获取从当天开始的 7 天训练安排                                                     |

### 1.2 PlanSession（计划阶段）

`PlanSession` 类的属性与函数的详细说明可查看表 1-2。

**业务规则**：

1. 三阶段顺序固定不可调整，符合运动生理学训练原则。
2. 三个阶段的目标肌群需保持一致性。
3. 热身阶段仅包含 `warmup` 类别动作，拉伸阶段仅包含 `cooldown` 类别动作。
4. 正式训练阶段根据计划类型选择动作（减脂：无氧 + 有氧；增肌：力量）。

**表 1-2 PlanSession 对象**

| 属性/函数           | 类型                      | 说明                                                 |
| :-------------- | :---------------------- | :------------------------------------------------- |
| `sessionId`     | String                  | 阶段唯一标识符，系统自动生成                                     |
| `planId`        | String                  | 关联计划 ID                                            |
| `sessionType`   | String                  | 阶段类型，严格限定三类：`warmup`（热身）、`main`（正式）、`cooldown`（拉伸） |
| `sequenceOrder` | Integer                 | 阶段执行顺序（1=热身，2=正式，3=拉伸），系统自动生成且不可调整                 |
| `targetMuscles` | List<String>            | 该阶段目标肌群列表，需与同一计划的其他阶段保持一致                          |
| `actionItems`   | List<SessionActionItem> | 该阶段包含的动作项集合，按执行顺序排列                                |

### 1.3 SessionActionItem（阶段动作项）

`SessionActionItem` 类的属性与函数的详细说明可查看表 1-3。

**业务规则**：

1. 支持用户记录每组的训练重量，系统生成计划时重量为空。
2. 休息时长默认 60s（减脂无氧/增肌/休息弹窗默认），用户可调整（30s 至 5 分钟）。
3. 支持动作替换、添加（需符合器材约束）、删除。
4. 每组完成后触发休息倒计时，结束后播放提示音。

**表 1-3 SessionActionItem 对象**

| 属性/函数                | 类型          | 说明                                    |
| :------------------- | :---------- | :------------------------------------ |
| `itemId`             | String      | 动作项唯一标识符，系统自动生成                       |
| `actionId`           | String      | 引用的训练动作 ID，关联 `TrainingAction` 对象     |
| `sets`               | Integer     | 组数，范围 1-6 组（默认 4 组）                   |
| `repsPerSet`         | Integer     | 每组次数，仅适用于力量训练类动作，范围 5-20 次/组（默认 12 次） |
| `durationMinutes`    | Integer     | 持续时长（分钟），仅适用于有氧动作（默认 30 分钟）           |
| `restSecondsDefault` | Integer     | 默认组间休息时间（秒），范围 30-300 秒（默认 60 秒）      |
| `weightRecords`      | List<Float> | 每组训练的重量记录（kg），生成时为空，用户训练时填写           |
| `completionStatus`   | Boolean     | 动作项完成状态                               |
| `startTimer()`       | 函数          | 开始训练计时                                |
| `stopTimer()`        | 函数          | 结束训练计时                                |
| `completeSet()`      | 函数          | 完成一组动作，触发休息倒计时                        |

### 1.4 TrainingSchedule（训练日程）

`TrainingSchedule` 类为新增对象，用于管理 7 天训练安排及延后逻辑。详细说明可查看表 1-4。

**业务规则**：

1. 页面中只显示从当天开始的 7 天训练安排。
2. 支持延后训练，可延后一天、两天、三天。
3. 根据计划的循环规则（如练 3 休 1）自动生成日程。

**表 1-4 TrainingSchedule 对象**

| 属性/函数           | 类型      | 说明                                           |
| :-------------- | :------ | :------------------------------------------- |
| `scheduleId`    | String  | 日程唯一标识符                                      |
| `planId`        | String  | 关联计划 ID                                      |
| `scheduledDate` | Date    | 计划训练日期                                       |
| `sessionId`     | String  | 当次训练对应的阶段 ID（通常指正式训练阶段）                      |
| `status`        | String  | 状态（"PLANNED"/"COMPLETED"/"POSTPONED"/"REST"） |
| `postponeCount` | Integer | 延后次数，限制最大延后 3 天                              |
| `postpone()`    | 函数      | 延后训练，参数为延后天数（1-3）                            |

## 二、业务规则详细说明

### 2.1 计划生成前置条件

1. **器材约束**：生成计划时，系统必须从指定健身房（器材清单）中所拥有的器材所支持的动作中进行选择。若用户器材清单为空，不可生成计划。
2. **经验水平**：动作难度需符合用户的经验水平。
3. **目标选择**：用户在生成计划页面首先需要选择生成"减脂计划"还是"增肌计划"。

### 2.2 减脂计划生成逻辑

1. **阶段结构**：包含热身、正式训练、拉伸三个阶段，三个阶段的目标肌群需保持一致性。
2. **热身阶段**：系统推荐 3 个动作，确保能够激活将要训练的肌群。
3. **正式训练阶段**：
   - **顺序**：必须先做无氧运动，然后做有氧运动。
   - **无氧运动**：默认为 4 个力量动作。每个动作做 4 组，每组 12 次。组间休息默认 60s（用户可调整，范围 30s-5 分钟）。支持用户添加组数、调整次数。重量字段为空，支持用户记录。
   - **有氧运动**：默认为 30 分钟的跑步机爬坡。用户可修改运动时长。若用户器材清单无跑步机，则推荐其他有氧器材动作。
4. **拉伸阶段**：系统推荐 3 个动作，确保拉伸到已经训练的肌群。
5. **循环规则**：默认按"练 3 休 1"连续循环训练。

### 2.3 增肌计划生成逻辑

1. **方案选择**：支持四种分化方案（一分化、二分化、三分化、四分化）。
2. **阶段结构**：每个方案都包括热身、正式训练、拉伸三个阶段，三个阶段的目标肌群需保持一致性。
3. **热身与拉伸**：系统根据正式训练的目标肌群，推荐激活和拉伸动作。
4. **正式训练阶段**：只支持力量动作。重量字段为空，支持用户记录。组间休息默认 60s（用户可调整，范围 30s-5 分钟）。
5. **分化方案详情**：
   - **一分化方案**：
     - 内容：每次训练练遍全身所有主要肌群（胸、背、腿、肩、手臂等）。
     - 频率：每周练 3 次，练一天休一天。
     - 动作量：默认 6 个力量动作，每个动作 4 组，每组 12 次。
   - **二分化方案**：
     - 内容：分为"上肢日"和"下肢日"。
     - 频率：练 2 休 1 循环。第一天上肢，第二天下肢，第三天休息。
     - 动作量：默认 4 个力量动作，每个动作 4 组，每组 12 次。
   - **三分化方案**：
     - 内容：分为"推日"（胸、肩、三头）、"拉日"（背、二头）、"腿日"（大腿、小腿）。
     - 频率：练 3 休 1 循环。第一天推日，第二天腿日，第三天拉日，第四天休息。
     - 动作量：默认 4 个力量动作，每个动作 4 组，每组 12 次。
   - **四分化方案**：
     - 内容：分为胸三头、背二头、肩、腿。
     - 频率：练 2 休 1，练 2 休 2 循环。第一天胸三头，第二天背二头，第三天休息，第四天肩，第五天腿，第六、七天休息。
     - 动作量：默认 4 个力量动作，每个动作 4 组，每组 12 次。

### 2.4 训练执行与交互规则

1. **计时功能**：点击"开始训练"按钮后开始计时，点击"结束"按钮后结束计时。
2. **休息倒计时**：每完成一组动作后，用户点击"确认完成"按钮，自动弹出倒计时窗口。
   - 默认时长：60 秒。
   - 调整范围：30 秒至 5 分钟。
   - 提示音：倒计时结束后，系统播放"滴"的声音提示用户进行下一组训练。
3. **动作管理**：
   - **替换**：可以替换所有的训练动作，系统给出可替换的动作推荐（需符合器材约束）。
   - **添加**：可以从动作库添加训练动作，但只能添加指定健身房中所拥有的器材所支持的动作。
   - **删除**：可以删除训练动作。
4. **日程管理**：
   - **7 天视图**：页面中只显示从当天开始的 7 天训练安排。
   - **延后训练**：如果当天有事可以延后训练，支持延后一天、两天、三天。

## 四、数据库 schema 变更说明

为支持新的业务逻辑，需对数据库表结构进行以下变更：

1. **`training_plan`** **表**：
   - **删除字段**：`valid_days` (INT), `total_duration_minutes` (INT)。
   - **新增字段**：
     - `plan_type` (ENUM): 'FAT\_LOSS', 'MUSCLE\_GAIN'。
     - `scheme_type` (ENUM): 'ONE\_SPLIT', 'TWO\_SPLIT', 'THREE\_SPLIT', 'FOUR\_SPLIT' (nullable, 仅增肌计划使用)。
     - `cycle_rule` (VARCHAR): 存储循环规则描述（如"练 3 休 1"）。
   - **修改字段**：`fitness_goal` 字段约束改为仅允许 'FAT\_LOSS', 'MUSCLE\_GAIN'。
2. **`session_action_item`** **表**：
   - **新增字段**：
     - `rest_seconds_default` (INT): 默认休息时长（默认 60 秒）。
     - `weight_records` (JSON): 存储每组重量记录，如 `[10.5, 10.5, 10.0, 10.0]`。
     - `duration_minutes` (INT): 用于有氧动作时长（nullable）。
3. **新增表** **`training_schedule`**：
   - 用于存储 7 天训练日程及延后状态。
   - 字段：`schedule_id` (PK), `plan_id` (FK), `scheduled_date` (DATE), `session_id` (FK), `status` (VARCHAR), `postpone_count` (INT)。
