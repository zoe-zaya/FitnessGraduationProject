# 用户管理模块 API 接口设计文档

## 1. 文档概述

### 1.1 编写目的

本文档定义了“基于深度学习的健身管理系统”中**用户管理模块**的 API 接口规范。旨在为前端开发（微信小程序）与后端开发（FastAPI）提供统一的交互标准，确保系统满足《需求规格说明书》中关于用户注册、登录、信息管理及安全性的业务要求。

### 1.2 适用范围

本模块涵盖用户认证、个人资料管理、身体数据管理及账号安全功能。对应《需求规格说明书》第 3.2 节用例分析中的以下用例：

- 注册、登录、忘记密码
- 编辑身体数据、编辑个人资料、编辑账号与安全

### 1.3 基础规范

- **通信协议**: HTTP/HTTPS
- **数据格式**: JSON (`application/json`)
- **字符编码**: UTF-8
- **认证方式**: JWT (JSON Web Token)，Bearer 模式
- **基础路径**: `/api`

---

## 2. 认证与授权

### 2.1 认证机制

除登录、注册、忘记密码接口外，所有接口需在 Request Header 中携带 Token。

- **Header Key**: `Authorization`
- **Header Value**: `Bearer <access_token>`

### 2.2 通用响应结构

```json
{
  "code": 200,          // 业务状态码，200 表示成功
  "message": "success", // 响应消息
  "data": {}            // 业务数据 payload
} 
```

## 3. 接口详细定义

### 3.1 用户注册✅

- **接口描述**: 用户通过手机号和密码创建账号。
- **对应用例**: 注册 (3.2 节)
- **业务规则**: 密码长度>8，含大小写数字符号；两次密码需一致。

| 项目         | 内容                   |
|:---------- |:-------------------- |
| **URL**    | `/api/auth/register` |
| **Method** | `POST`               |
| **Auth**   | 不需要                  |

**请求参数 (Body)**:

```json
{
  "phone": "18812341234",      // String, 必填，11 位手机号
  "password": "TestPass123!", // String, 必填，密码
  "confirm_password": "TestPass123!" // String, 必填，确认密码
}
```

**响应参数 (Data)**:

```json
{
    "message": "注册成功",
    "user_id": "7c8a21e2-46f1-4d1f-b331-d90970c83123"
}
```

**异常场景**:

- 手机号已存在 →返回400（提示重新注册）
- 密码不符合复杂度 →返回422（提示密码不符合复杂度）
- 两次密码不一致 → 返回422（提示两次密码不一致）

### 3.2 用户登录✅

- **接口描述**: 用户通过手机号和密码登录系统，获取访问令牌。
- **对应用例**: 登录 (3.2 节)
- **业务规则**: 验证手机号是否存在，密码是否匹配。

| 项目         | 内容                |
|:---------- |:----------------- |
| **URL**    | `/api/auth/login` |
| **Method** | `POST`            |
| **Auth**   | 不需要               |

**请求参数 (Body)**:

```json
{
  "phone": "13800138000",
  "password": "SecurePass123!"
}
```

**响应参数 (Data)**:

```json
{
    "access_token": "eyJhbGciOiJIUzI...", // JWT Token
    "token_type": "bearer",
    "user_info": {
        "user_id": "7c8a21e2-46f1-4d1f-b331-d90970c83123",
        "name": "用户7c8a21",
        "phone": "18812341234"
    }
}
```

**异常场景**:

- 手机号未注册 → 返回 400 (提示先去注册)
- 密码错误 → 返回 400 (提示密码错误)

### 3.5 编辑个人资料✅

- **接口描述**: 用户更新昵称、头像、生日。
- **对应用例**: 编辑个人资料 (3.2 节)
- **业务规则**: 
  1. 昵称不可重复 (扩展事件流 8a)。
  2. 生日更新后需重新计算年龄 (用例步骤 12)。
  3. 生日格式为 YYYY-MM-DD。

| 项目         | 内容                  |
|:---------- |:------------------- |
| **URL**    | `/api/user/profile` |
| **Method** | `PUT`               |
| **Auth**   | **需要**              |

**请求参数 (Body)**:

```json
{
  "name": "新昵称",             // Strinf, 1-64 字符
  "avatar_url": "https://...", // String
  "birthday": "2000-01-01"     // Date, YYYY-MM-DD
}
```

**响应参数 (Data)**:

```json
{
  "user_id": "uuid-string",
  "name": "新昵称",
  "age": 26,                   // 返回更新后的年龄
  "message": "个人资料更新成功"
}
```

**异常场景**:

- 昵称已存在 → 返回 400（提示昵称已存在，重新输入）

### 3.6 检查资料完整性✅

- **接口描述**: 检查用户是否已录入生成训练计划所需的基本信息。
- **对应业务规则**: 用户首次使用系统时必须完成基本信息录入，否则无法生成个性化训练计划 (2.2.1 节)。
- **用途**: 前端在用户点击“生成计划”前调用此接口进行拦截校验。

| 项目         | 内容                                 |
|:---------- |:---------------------------------- |
| **URL**    | `/api/user/check-profile-complete` |
| **Method** | `GET`                              |
| **Auth**   | **需要**                             |

**响应参数 (Data)**:

```json
{
  "is_complete": true,         // Boolean
  "missing_fields": [],        // Array, 缺失的字段列表 (如 ["height", "fitness_goal"])
  "message": "资料完整"        // 或 "请先完善身体数据"
}
```

### 3.7 发送验证码✅

- **接口描述**: 发送用于重置密码的验证码。

- **对应用例**: 忘记密码 (3.2 节步骤3)

- **业务规则**: 
  
  * 验证手机号是否已注册（扩展事件流 4a）
  
  * 同一手机号 60 秒内不能重复发送
  
  * 验证码有效期 5 分钟（300 秒）
  
  * 开发环境验证码输出到控制台，生产环境调用短信服务

| 项目         | 内容                                 |
| ---------- | ---------------------------------- |
| **URL**    | `/api/auth/send-verification-code` |
| **Method** | `POST`                             |
| **Auth**   | 不需要                                |

**请求参数 (Body)**:

```json
{
  "phone": "18802217361"
}
```

**响应参数 (Data)**:

```json
{
    "message": "验证码已发送",
    "expire_seconds": 300
}
```

**异常场景**

| 场景      | 状态码 | 错误信息               |
| ------- | --- | ------------------ |
| 手机号未注册  | 400 | "该手机号未注册，请先注册"     |
| 发送间隔太短  | 429 | "验证码已发送，请 XX 秒后再试" |
| 手机号格式错误 | 422 | "请输入有效的手机号"        |

---

### 3.8 验证验证码✅

- **接口描述**：验证输入的验证码是否正确。

- **对应用例**：忘记密码（3.2节步骤4）

- **业务规则**：
  
  * 验证验证码是否正确（扩展事件流 4b）
  
  * 验证验证码是否过期
  
  * 验证验证码是否已使用
  
  * 最大尝试次数 5 次，超过后验证码失效

| 项目         | 内容                      |
| ---------- | ----------------------- |
| **URL**    | `/api/auth/verify-code` |
| **Method** | `POST`                  |
| **Auth**   | 不需要                     |

**请求参数 (Body)**:

```json
{
  "phone": "18802217361",
  "code": "427447"
}
```

**响应参数 (Data)**:

```json
{
    "message": "验证码验证成功",
    "is_valid": true
}
```

**异常场景**

| 场景     | 状态码 | 错误信息               |
| ------ | --- | ------------------ |
| 验证码不存在 | 400 | "验证码不存在，请先获取验证码"   |
| 验证码错误  | 400 | "验证码错误，剩余 X 次尝试机会" |
| 验证码已过期 | 400 | "验证码已过期，请重新获取"     |
| 验证码已使用 | 400 | "验证码已使用，请重新获取"     |
| 尝试次数过多 | 400 | "验证次数过多，请重新获取验证码"  |

---

### 3.9 重置密码 (忘记密码)✅

- **接口描述**: 用户通过手机号和验证码重置登录密码。

- **对应用例**: 忘记密码 (3.2 节)

- **业务规则**: 
  
  * 验证手机号是否已注册（扩展事件流 4a)
  
  * 验证验证码是否正确且未过期（扩展事件流 4b）
  
  * 密码复杂度校验（扩展事件流 6a）：
    
    * 长度≥8 个字符
    
    * 包含大写字母
    
    * 包含小写字母
    
    * 包含数字
    
    * 包含特殊符号（!@#$%^&*()_+-=）
  - 两次密码一致性校验（扩展事件流 6b）
  
  - 密码重置成功后清除验证码

| 项目         | 内容                         |
| ---------- | -------------------------- |
| **URL**    | `/api/auth/reset-password` |
| **Method** | `POST`                     |
| **Auth**   | 不需要                        |

**请求参数 (Body)**:

```json
{
  "phone": "18802217361",
  "new_password": "NewPass123!",
  "confirm_password": "NewPass123!"
}
```

**响应参数 (Data)**:

```json
{
  "message": "密码重置成功"
}
```

**异常场景**

| 场景      | 状态码 | 错误信息                |
| ------- | --- | ------------------- |
| 密码长度不足  | 422 | "密码长度需大于 8 个字符"     |
| 缺少大写字母  | 422 | "密码需包含大写字母"         |
| 缺少小写字母  | 422 | "密码需包含小写字母"         |
| 缺少数字    | 422 | "密码需包含数字"           |
| 缺少特殊符号  | 422 | "密码需包含特殊符号"         |
| 两次密码不一致 | 422 | "确认密码与新密码不一致，请重新输入” |

---

### 3.10 修改手机号✅

- **接口描述**：修改绑定的手机号。

- **对应用例**：编辑账号与安全（3.2节步骤3和4）

- **业务规则**：
  
  - 旧手机号是否正确（对应用例扩展事件流 4a）
  
  - 验证新手机号格式是否正确（对应用例扩展事件流 4b）
  
  - 验证新手机号是否已被其他用户注册
  
  - 更新数据库中的手机号 

| 项目         | 内容                         |
| ---------- | -------------------------- |
| **URL**    | `/api/user/security/phone` |
| **Method** | `PUT`                      |
| **Auth**   | 需要                         |

**请求参数 (Body)**:

```json
{
  "old_phone": "18802217361",
  "new_phone": "13900139000"
}
```

**响应参数 (Data)**:

```json

    "message": "手机号修改成功",
    "old_phone": "18802217361",
    "new_phone": "13900139000"

```

**异常场景**

| 场景         | 状态码 | 错误信息                    |
| ---------- | --- | ----------------------- |
| 旧手机号错误     | 400 | "输入的旧手机号不正确，请检查后重试"     |

## 5. 安全性说明

1. **密码存储**: 后端必须使用 bcrypt 或类似算法对密码进行哈希存储，严禁明文存储。
2. **传输安全**: 生产环境必须使用 HTTPS 协议加密传输。
3. **Token 有效期**: Access Token 有效期建议设置为 30 分钟，过期需刷新或重新登录。
4. **敏感信息**: 接口响应中严禁返回用户密码哈希值。

## 6. 附录：接口调用流程示例

**生成训练计划前的校验流程**:

1. 前端调用 `GET /api/user/check-profile-complete`。
2. 若 `is_complete` 为 `false`，跳转至 `编辑身体数据` 页面。
3. 用户填写完毕后调用 `PUT /api/user/body-data`。
4. 再次校验通过后，允许调用 `生成训练计划` 接口。
